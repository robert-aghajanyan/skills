# Docs Accuracy

Use this reference when developer workflow docs need to be checked against actual repo behavior.

## Evidence To Compare

- README quickstarts, setup guides, contributing docs, architecture docs, runbooks, examples, release docs, and CI/deploy docs.
- Concrete claims: commands, paths, flags, package managers, env vars, ports, local services, generated files, prerequisites, expected outputs, and validation steps.
- Actual sources of truth: manifests, package scripts, Makefiles, CI workflows, Docker files, env templates, config parsers, test config, and source code.

## Checks

- Documented commands exist, use current flags, and run from the documented working directory.
- Referenced files and directories exist or are generated by a documented command.
- Docs name the recommended path when multiple setup or test paths exist.
- Prerequisites are explicit enough for a fresh checkout, including credentials, services, ports, tool versions, and platform assumptions.
- Expected outputs match current behavior closely enough to help a developer know whether the step worked.
- Troubleshooting docs address likely first-run failures, not only production incidents.

## Finding Boundary

Report documentation issues only when they affect developer workflow quality. Examples include broken setup, wrong commands, missing required env vars, confusing CI reproduction steps, stale generated-file instructions, or unsafe release/deploy guidance.

Do not report pure prose style, missing exhaustive internals, or doc rewrites that do not change what a developer can do.

## Common Findings

- A README command references a removed script after the repo moved to a task runner.
- Docs describe `docker-compose` while the repo only has `docker compose` examples or a different compose file name.
- A contributing guide says to run all tests, but the repo has a focused command that developers need for routine changes.
- Env docs list variables with old names after config keys were renamed.
- Troubleshooting steps assume CI-only secrets or cloud access without saying so.
